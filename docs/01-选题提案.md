## 0. 结论先行

**选定的方向：给 dsh 补上「隔离执行地基」——把 shell / 文件 / 进程 / 终端 / 后台任务这一整层执行能力，从"宿主本地"扩展到容器（后续 microVM / 远程）。**

- 项目代号：**`dsh-runbox`**（npm 名 `dsh-runbox` 已验证未被占用；备选 `dsh-cage`、`dsh-container`）
- 一句话定位：**让 agent 在你的机器"旁边"干活，而不是在你的机器"上面"干活**——一次性、可丢弃、有资源与网络边界、可审计的执行环境。
- 关键依据：DeepSeek Harness 官方文档明确写了「容器、microVM 和远程执行是完整能力 seam 的**同级实现**」，但官方仓库**一个都没实现**；社区 4646 个插件里**同样一个都没有**（详见第 2、3 节）。

## 2. 官方架构里的"空位"（这不是我猜的，是官方文档写的）

dsh 是"一切皆插件"，所有能力都挂在 **capability seam** 上。官方 `docs/capability-seams.zh.md` 给出 72 项服务，其中 29 项是**可替换的 seam**。逐项对照"官方实现 / 社区实现"后，真正的空位只有一个：

> `docs/subsystems/sandbox.zh.md` 第 5 行原文：
> **「容器、microVM 和远程执行是完整能力 seam 的同级实现，而非 `ctx.sandbox` 的提供方。」**

这句话的含义完全改变了方向选择：

- 官方**不是**想让你去实现 `ctx.sandbox.confine()`（那已经由 `sandbox-local` 用 Linux bwrap/Landlock、macOS Seatbelt、Windows ACL 受限令牌覆盖了，Windows 下还是 `partial` 强制）。
- 官方想让你实现的是**同级的一整套 sibling providers**：`ctx.subprocess` / `ctx.fs` / `ctx.shell` / `ctx.terminals` / `ctx.jobs`——把"执行发生在哪"整体搬走。
- 官方把这三类（容器 / microVM / 远程）**点名列出来，却一个都没交付**。这是官方亲手标出的空位。

同时，官方在 shell seam 上主动留了话：

> 沙箱、远程或 PowerShell 执行器**可以替换** `bash-local`，而无需改动任何消费方。

## 4. 三个候选方案与取舍

| | A. 隔离执行地基（推荐） | B. 凭据安全后端 | C. 团队化 / 多租户 |
|---|---|---|---|
| 内容 | 容器/microVM 的 subprocess·fs·shell·terminal·jobs providers | `ctx.credentials` 接到 OS 钥匙串（DPAPI/Keychain/libsecret）+ 轮换 + 审计 | 登录墙 + RBAC + 隔离工作区 + 配额 + 审计 |
| 官方空位 | ✅ 文档点名的三大同级实现之一 | ⚠️ `ctx.credentials` 官方仅 1 个实现，但属"可替换"而非"未实现" | ❌ 与 local-first 定位相悖，官方无此 seam |
| 社区竞争 | **接近 0** | 仅 586 / 1113 两个小包 | 4 个，均 <450 下载（很薄） |
| 工程深度 | 高（进程/PTY/文件/生命周期/跨平台/fail-closed） | 中 | 高，但更像"再做一个 Web 应用" |
| 价值叙事 | agent 自主化的**信任前提**：敢让它过夜跑 | 密钥不再明文躺在配置里 | 团队共享一台 dsh |
| 可本地验证 | ✅ 本机已有 Docker 29.3.1 | ✅ | ⚠️ 需要多机/多账号 |
| 结论 | **采纳** | 备选（可作后续第二项目） | 暂缓（偏离 harness native 路线） |

**为什么 A 比"再做一个 xx 功能插件"强**：它不解决某个具体小痛点，而是**把整套执行地基换掉**。上层所有已有插件（审批、权限、成本、审计、评测）都不用改，就能自动获得"受限环境"这层能力——这正是 capability seam 的设计意图，也是最容易被官方与社区接受的贡献形态。

## 5. 推荐方案架构

### 5.1 系统全景

```
                    ┌─────────────────────────────────────────┐
   dsh 上层（不改）  │  agent-loop · tool-bash · tool-fs ·      │
                    │  tool-terminal · tool-jobs · 审批/权限    │
                    └──────────────────┬──────────────────────┘
                                       │ 只认 seam，不认实现
   ┌───────────────────────────────────▼───────────────────────────────────┐
   │                        dsh-runbox（本项目）                            │
   │                                                                       │
   │  core        后端注册表 · 会话↔沙箱绑定 · 策略翻译 · fail-closed 守卫   │
   │              · 审计记录 · 孤儿回收                                     │
   │                                                                       │
   │  providers   subprocess │ fs │ shell │ terminal │ jobs                 │
   │              （实现官方 seam 契约，可整体替换本地实现）                  │
   │                                                                       │
   │  backends    docker/podman(E1)  │  wsl2(E2)  │  microVM(E3) │ ssh(E4)   │
   │              └────── 同一 provider 接口，后端可插拔 ──────┘             │
   │                                                                       │
   │  ui          设置卡（镜像/资源/网络） · 状态面板 · 审计时间线            │
   └───────────────────────────────────┬───────────────────────────────────┘
                                       │ Engine API（npipe / unix socket）
                       ┌───────────────▼────────────────┐
                       │  一次性容器：只读 rootfs + tmpfs │
                       │  工作区同路径 bind mount         │
                       │  cgroup 限额 · 默认无网络        │
                       └────────────────────────────────┘
```

### 5.2 包结构（monorepo，pnpm workspaces）

| 包 | 职责 |
|---|---|
| `@dsh-runbox/core` | 后端注册表、会话↔沙箱绑定、`SandboxMode → 箱内策略` 翻译、强制执行上报、fail-closed、审计记录、孤儿 GC |
| `@dsh-runbox/backend-docker` | Docker/Podman Engine API 客户端（走 npipe/unix socket，**不依赖 docker CLI**）：镜像解析与拉取、箱生命周期、工作区挂载、cgroup 限额、网络模式、按 label 回收 |
| `@dsh-runbox/provider-subprocess` | 实现 `ctx.subprocess`：spawn 进箱、stdio 接管、退出码、kill 升级、进程树 |
| `@dsh-runbox/provider-fs` | 实现 `ctx.fs`：stat/read/write/edit 路由进箱，遵守 `workspaceRoot` 与模式 |
| `@dsh-runbox/provider-shell` | `ctx.shell` 的箱内 bash 执行器，替换 `bash-local` |
| `@dsh-runbox/provider-terminal` | `ctx.terminals`：箱内持久 PTY |
| `@dsh-runbox/provider-jobs` | `ctx.jobs`：后台任务在箱内登记、可查可杀 |
| `@dsh-runbox/sandbox-bridge` | `ctx.sandboxPolicy` 的策略翻译；把"容器边界"作为 `enforcement: full` 上报 |
| `@dsh-runbox/ui` | Web 设置卡 + 状态面板 + 审计时间线（`ConversationNodeDefinition` / keyed renderer） |
| `@dsh-runbox/conformance` | 契约测试套件：同一套用例可打任意后端（spawn/读写/PTY/kill/fail-closed/拒绝分类） |

### 5.3 关键机制（对齐官方契约）

- **策略**：`ctx.sandboxPolicy.resolve()` 是唯一真源。`read-only` → 箱内 rootfs 只读、工作区只读挂载；`workspace-write` → 工作区读写、临时区 tmpfs；`danger-full-access` 按官方约定**不进入 seam**（消费方直连 spawn）。任何情况下**静默降级为不隔离都是非法的**（官方原文禁止）。
- **失败即拒绝**：Docker 不可用、镜像缺失、后端探测失败 → 抛 `SandboxUnavailableError`，绝不静默回落到宿主执行。
- **拒绝分类**：按官方 `ConfinedArgv` 契约上报 `denialSignatures`（容器内 EROFS/EACCES/EPERM）与 `runnerFailureRules`，让上层能区分"沙箱拦住了"与"沙箱自己坏了"。
- **注册即可逆**：所有注册包在 `ctx.effect` 内，支持热重载与干净卸载（卸载时回收容器）。
- **审计**：每次受限执行产出记录（argv 摘要、退出码、耗时、超时、强制执行度），经 `ctx.sessionTelemetry` 落到会话日志——天然可回放。
- **安全默认**：不挂载宿主 docker socket 进箱；drop 全部 capabilities；rootfs 只读；默认 `network: none`；密钥默认不进环境变量。

## 6. 里程碑

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| **M0 契约打样** | 拉取并吃透 `@deepseek-ai/dsh-{subprocess,fs,shell,terminal,jobs,sandbox-policy}` 的 `.d.ts`；跑通最小 dsh 启动；仓库骨架 + CI | 能在本地 `dsh web` 跑起来并加载一个空插件 |
| **M1 最小闭环** | `core` + `backend-docker` + `provider-subprocess` + `provider-shell` | 一次 `bash` 调用真实执行在容器内；宿主上无副作用；容器不可用时 fail-closed |
| **M2 文件层** | `provider-fs` + 挂载语义 + 策略翻译 + 强制执行上报 | 读写/编辑全部走箱；`read-only` 下写操作被拒且拒绝原因正确分类 |
| **M3 会话层** | `provider-terminal` + `provider-jobs` + 会话级生命周期 + 孤儿回收 | 持久 PTY 可用；后台任务可查可杀；异常退出无残留容器 |
| **M4 产品化** | `ui`（设置/状态/审计）+ 网络与资源策略 + 文档站 + 一键安装 | 设置页可切镜像/CPU/内存/网络；审计时间线可视化 |
| **M5 第二后端** | Podman / WSL2 / microVM / SSH 后端 + `conformance` 套件全绿 | 同一套契约测试在 ≥2 个后端上通过 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| dsh 处于 developer preview，**会有破坏性变更** | 依赖官方 seam 包而非内部实现；`dshTarget` 字段标注兼容版本；`conformance` 套件作为升级门禁 |
| Docker 未安装 / Windows npipe 差异 | M1 就做后端探测与清晰报错；Docker Desktop 与 Podman 双通道；后续补 WSL2 后端 |
| `fs` 走容器有性能开销 | 提供两档：直通 bind mount（快）与镜像模式（强隔离），由策略选择 |
| 范围蔓延到 microVM / 远程 | 后端全部藏在同一 provider 接口之后，M5 才开工 |
| 生态噪音大，发不出声 | 一开始就对齐官方文档语言与 naming；投稿 `dsh-plugin` topic + 社区市场；附一致性测试结果作为可信度证据 |
